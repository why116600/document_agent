## 新登记问题

DEF-016 来自同日 DeepSeek 温度 0 对照，见下文。

- **DEF-013 范围依据误拒。** CP-009 需求写“二、巡检表”时用中文引号，模型在 `basis_span` 中改成英文引号。`scope_contract.is_grounded` 只做 NFKC 和去空白，判为 `E_SCOPE_UNGROUNDED`。两次运行均复现，DEF-005 的端到端回归因此被阻断。
- **DEF-014 图谱精确标识检查误拒正常资料。** KG-WORD 在线运行时，检索计划实体为“星桥、星桥项目、KG-DEMO-20261102”。测试标识只在原文分块中，不是实体名，`_missing_plan_entities` 判为未找到，正常可写的说明未生成。该检查使用子串匹配，泛化实体也可能使具体名称被判为已命中。
- **DEF-016 约束校验要求保留用户排除的干扰数值。** CP-002 修复稿被判 `protected_fact_missing:1小时`、`2小时`。原资料中这两个数值只出现在“T1的2小时、L8的1小时不适用于E2”，需求明确不使用 T1、L8 规则。修复稿遵守需求反而无法通过校验。
- **DEF-015 仅格式调整时改变段落层级。** CP-010 正文“记录保留45天……”与原 Title 均被写为 Heading 2 并带大纲级别。页面外观无明显变化，导航窗格和目录会出现错误标题。日志显示本次显式未要求大纲，却开启了大纲写入。

## 执行与限制

1. 所有运行都使用干净的独立检出目录，并核对加载的业务模块来源。15 个用例各执行 1 次，CP-009、CP-003 另执行第 2 次，单独记录。所有输入哈希保持，没有越界写入，也没有超时。
2. 改写例逐段、逐 Run、逐单元格与原稿比对，包括页眉。保存的 5 份 Word 均用 WPS 只读导出并查看页面。未保存的用例根据日志核对草稿字数和检查项，不以程序自报替代内容判定。
3. 复用历次 WorkBuddy 传输适配器。候选新增的 `structured_invoke` 使用指定工具名的 `tool_choice`，WorkBuddy 返回 400。测试接入层改为字符串 `required`，保留 LangChain 原有的 `raw/parsed/parsing_error` 组合，未改产品代码。WorkBuddy 无法强制调用指定工具，因此 CP-003 的“无可解析结构”尚不能直接归为产品问题。建议另用 DeepSeek 官方接口复测。
4. 另有 19 项离线定向检查，全部通过，未调用模型。样本量小，不作稳定性或质量提升的统计结论。原始日志和模型往来留在本机，不随材料提交。

**建议。** 先修 DEF-014、DEF-015、DEF-016 和 DEF-013，再处理 DEF-004 普通新建的超长重复。之后在固定修复提交上，以 Hy3 和 DeepSeek 温度 0 复跑 CP-002、CP-009、CP-010、KG-WORD、KG-NO-MATCH 和 SK-003。通过后再由开发合入 develop。测试与开发宜约定同一模型和温度。
