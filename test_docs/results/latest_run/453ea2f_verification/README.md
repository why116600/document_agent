## 新登记问题

- **DEF-013 范围依据误拒。** CP-009 需求写“二、巡检表”时用中文引号。CP-009@Hy3 和 CP-009-R2@Hy3 中，模型在 `basis_span` 里改成英文引号。`scope_contract.is_grounded` 只做 NFKC 和去空白，判为 `E_SCOPE_UNGROUNDED`。CP-009@DS-T0 保留了中文引号，未触发。
- **DEF-014 图谱精确标识检查误拒正常资料。** KG-WORD 001@Hy3 的检索计划实体为“星桥、星桥项目、KG-DEMO-20261102”，KG-WORD 001@DS-T0 为“星桥、KG-DEMO-20261102”。测试标识只在原文分块中，不是实体名，`_missing_plan_entities` 判为未找到，正常可写的说明未生成。该检查使用子串匹配，泛化实体也可能使具体名称被判为已命中。
- **DEF-015 仅格式调整时改变段落层级。** CP-010@Hy3 与 CP-010@DS-T0 中，正文“记录保留45天……”与原 Title 均被写为 Heading 2 并带大纲级别。页面外观无明显变化，导航窗格和目录会出现错误标题。日志显示本次未要求大纲，却开启了大纲写入。
- **DEF-016 约束校验要求保留用户排除的干扰数值。** CP-002@DS-T0 修复稿被判 `protected_fact_missing:1小时`、`2小时`。原资料中这两个数值只出现在“T1的2小时、L8的1小时不适用于E2”，需求明确不使用 T1、L8 规则。修复稿遵守需求反而无法通过校验。

## 执行与限制

1. 所有运行都使用干净的独立检出目录，并核对加载的业务模块来源。共 30 次运行：`@Hy3` 15 次，其中含 CP-009-R2 和 CP-003-R2；`@DS` 2 次；`@DS-T0` 13 次。所有输入哈希保持，没有越界写入，也没有超时。
2. 改写例逐段、逐 Run、逐单元格与原稿比对，包括页眉。归档的 7 份 Word 均用 WPS 只读导出并查看页面。未保存的运行根据日志核对草稿字数和检查项，不以程序自报替代内容判定。
3. 复用历次 WorkBuddy 传输适配器。候选新增的 `structured_invoke` 使用指定工具名的 `tool_choice`，WorkBuddy 返回 400。测试接入层改为字符串 `required`，保留 LangChain 原有的 `raw/parsed/parsing_error` 组合，未改产品代码。WorkBuddy 无法强制调用指定工具，因此 CP-003@Hy3 的“无可解析结构”尚不能直接归为产品问题。
4. 另有 19 项离线定向检查，全部通过，未调用模型。样本量小，不作稳定性或质量提升的统计结论。原始日志和模型往来留在本机，不随材料提交。
