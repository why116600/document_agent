# 测试协作与修改原则 v1.0.13

规则版本：v1.0.13。适用范围：本共享测试资料目录及获授权的测试任务。

## 测试职责

设计合成输入和预期，固定测试基线，运行用例，保留真实失败，登记可复现缺陷。测试不等于修复授权，不为通过测试而改产品代码或注入错误。通用疑点、未执行用例和环境适配不直接算确认缺陷。

## 修改原则

1. **原默认行为保持。** 未经明确产品变更授权，不改原入口、配置、模型请求、提示词、重试、保存、输出和退出语义。
2. **个人环境留本机。** 个人解释器路径、依赖缓存、服务配置、账户接入、凭据和运行历史不进入团队提交或共享文档。环境适配不登记为原项目缺陷。
3. **扩展独立启用。** 如另获授权增加调试或扩展能力，放在独立模块，通过独立配置和明确入口启用，默认关闭；不在默认链路里隐式切换模型或注入通用补丁。
4. **容易拆分。** 扩展代码、测试和说明单独提交；禁用或移除扩展后原流程无需跟着修改。先复用已有接口；新增接口范围最小、用途清楚。
5. **兼容结论要验证。** 对锁定版本审查差异并回归原默认流程，记录关闭/开启扩展时的结果。未验证则写未验证，不承诺绝对无影响。这些是后续改动要求，不表示现有产品已经完成改造。
6. **修复单独处理。** 原项目缺陷须有明确需求、真实复现与基线；获授权后才修，限定文件/函数并提供修改说明、交接及原例回归，不与测试规范混合提交。

## 文件与证据

新测试程序、合成样例、预期和脱敏结果统一放测试目录，逐文件检查后共享；目录位置不自动赋予上传授权。真实凭据、私人原始日志、请求响应和数据库留本机。

只读使用共享运行环境，安装、升级或卸载依赖须先取得用户确认。正式用例未运行不得写通过。缺陷表用 Markdown，稳定编号，单表最多 60 条；满额先归档再建立新版本，不丢失未关闭记录。

修改仅限任务范围，版本化文件使用递增版本和新名称，保留旧版。固定 README/AGENTS 入口在更新前保留历史。中文富文档使用宋体，所有文本黑色；Markdown 外观由平台控制，未实看不声称完成外观验收。

默认只读 Git；按用户明确授权逐文件暂存、提交或推送，不执行全目录或全工作区添加。当前范围见[共享交接](workflow_handover_v1.0.13.md)。

探索测试材料按用例、输入、事后整理预期、实际成果和报告分别归档；原件保留，复制件核对归档哈希。事后整理不能冒充运行前冻结，未记录的退出码/基线不补造；人工探索和正式用例独立计数，结构差异如实保留，不为整理而修成果。

## 固定执行和交付流程

后续每个测试按[单项工作流](test_workflow_v1.0.13.md)执行，并复制[执行清单](templates/run_checklist_v1.0.13.md)记录真实完成情况：选定对象 → 冻结输入 → 先定预期 → 执行 → 对照 → 判定归属 → 更新入口 → 检查移交。

README 必须先写结论/结果，再写观察与具体建议，最后链接详细证据。结论逐项对应报告，不从文件存在或静态检查成功推断业务通过。建议写可执行动作及是否已执行；不能凭模糊的“建议优化”替代下一步。

交付前运行[只读检查器](tools/check_test_delivery_v1.0.13.py)检查材料关联、哈希和链接，保留实际检查结果。工具失败应先说明缺件或错误，不能自动补出假记录；通过也不能替代事实判断、页面实看、DOCX 元数据审查和人工隐私检查。当前已归档两项探索与正式 36 条用例始终分开统计。
