# 单项测试执行清单模板 v1.0.13

模板版本：v1.0.13。**这是待复制的工作清单，不代表任何测试已执行或通过。** 为新批次另存有实际用例号和版本的新文件，再填写真实结果。不得把当前空勾选表当完成记录。

## 运行前

- [ ] 填明用例/子例、正式或探索、实际执行者、被测版本与可追溯基线。
- [ ] 明确授权入口、数据及资源范围，未擅自更新代码、模型或依赖。
- [ ] 原件、运行副本和输出分开，输入为合成/授权资料，运行前哈希已记录。
- [ ] 写清准确需求、内容范围、必须保留对象、字数口径、格式和保存方式。
- [ ] 需求不明确处已标待确认；若为先行探索，明确哪些预期尚未冻结。

## 执行与检查

- [ ] 保存实际输入要求、尝试记录、实际路由和退出状态；未知信息写未记录。
- [ ] 成功和失败成果均保留，没有为跑通而改产品、调换输入或删除失败。
- [ ] 核对事实/数字、修改范围、原稿哈希和保存路径。
- [ ] 核对字体颜色、表格/对象等结构；实际页面检查与 XML 检查分别记录。
- [ ] 逐项写实际结果与依据，整体判断没有超出已检查范围。
- [ ] 观察、需求待确认、环境阻塞与确认缺陷已分开，编号和统计没有混用。

## 材料与交付

- [ ] cases、inputs、expected、outputs、reports 和 manifest 关联同一用例。
- [ ] manifest 的当前哈希能匹配副本，运行前/事后归档的证据性质分清。
- [ ] README 先有结论和结果表，再有观察/具体建议，最后是证据导航。
- [ ] 建议写明下一步动作和是否已执行，没有编造通过数、工时或责任人。
- [ ] 只读交付检查已执行，记录实际退出码和发现；问题未解决时保留问题。
- [ ] 人工复核结论、可打开成果、共享文本及 DOCX 元数据；未验证项保留限制。
- [ ] 个人路径、账户/接入、凭据、完整原始日志和私人截图未纳入共享。
- [ ] 新旧版本及固定入口历史处理一致，原失败成果未被美化或覆盖。
- [ ] 共享文件逐项列出；暂存、提交和推送按用户明确授权执行。

## 必须填写的收尾结论

用实际事实填写：本次执行了什么；哪些检查符合/失败/待确认/未验证；新增确认缺陷是否有复现依据；下一步具体做什么；哪些结果不能外推。若清单尚有未完成项，记录原因和恢复条件，不统一打勾。

操作依据见[固定工作流](../test_workflow_v1.0.13.md)，当前材料示例见[两项探索](../exploration_v1.0.11/README.md)。
