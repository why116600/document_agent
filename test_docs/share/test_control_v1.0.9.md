# document_agent 测试控制文档 v1.0.9

文档版本：v1.0.9。状态：测试控制规则已编制，正式首轮未执行。本文件配合[计划](test_plan_v1.0.9.md)、[缺陷表](defect_register_v1.0.9.md)和[修改原则](AGENTS.md)使用。

## 1. 测试对象与基线

按锁定版本的[项目 README](../../README.md)确认功能承诺，记录软件版本、完整提交号、入口、授权配置和依赖版本。若有补丁，明确补丁标识和变更范围；不能仅写提交号就声称测试了未修改版本。

原项目测试与环境适配或个人扩展验证分别成批。个人适配的失败不自动计入原项目缺陷。个人路径、配置、接入和运行历史不进入团队文档；但不能隐瞒会影响测试结论的基线差异。必要时只共享经审查的版本/补丁标识与限制，无法在可共享基线上执行则据实记录未执行或阻塞。

正式执行前确认实际对象；不自动更新、切分支或更换基线。执行中不换代码、模型或输入来掩盖失败；确需变更时保留原批次，记录新对象并重新测试。默认 DeepSeek 配置以锁定版本公开说明为依据，不借用个人凭据作承诺外比较。

## 2. 环境与数据

共享环境只读，变更依赖须先获确认。使用授权测试实例和合成资料，不操作正式数据或其他进程。原件、运行副本和输出分离，记录哈希和恢复方式；不覆盖失败输出。

模型请求和知识录入会使用输入内容，仅使用授权资料。公开证据为必要脱敏摘要；真实凭据、原始请求响应、私人日志、数据库导出和截图留在本机。共享文件不链接到未共享私人证据。

## 3. 执行步骤与控制

| 阶段 | 准入与动作 | 退出条件 |
| --- | --- | --- |
| 范围准备 | 核对功能、确认需求和被测版本 | 基线、用例及待确认事项可定位 |
| 样例准备 | 制作合成输入、固定预期、保护原件 | 样例/哈希、检查口径和恢复办法完整 |
| 正式首轮 | 逐例执行，记录每次尝试与失败 | 所有纳入范围实例有真实状态和证据；未执行或阻塞有原因 |
| 缺陷移交 | 确认预期、最小复现和实际影响 | 具体问题可追溯，责任人未知写待指派 |
| 获授权修复后回归 | 使用原失败样例和原需求，再测影响范围 | 修复版本、回归证据与关闭/重开理由齐全 |

测试授权不包含修产品。通用修复与测试资料分开；调试或扩展必须另获授权，独立配置显式启用、默认关闭、便于拆分，并验证不改变原默认流程，不能先声称无害。

## 4. 结果判定

| 状态 | 条件 |
| --- | --- |
| 未执行 | 尚未启动实际步骤 |
| 执行中 | 当前已开始，记录实际进度 |
| 通过 | 所有明确预期、产物与必要证据核对通过 |
| 失败 | 实际行为与有依据的预期不符；缺陷确认和归属另外判断 |
| 阻塞 | 样例、版本、环境或需求条件不具备，记录恢复条件 |

保存成功、退出 0、ZIP 可读、文字一致都不能单独证明任务和格式正确。分别检查文件可打开、实际路径、内容/数字、未要求修改部分、表格/对象、字体颜色和原件哈希。XML 检查与页面实看分别记录。

需求口径不明先列待确认，不把偏好或静态疑点算缺陷。失败保留；后续一次成功不能删除前次失败。模型重试/补救的实际行为如发生，按被测版本据实记录，不能把不同路径结果混为同一次通过。

## 5. 执行记录与缺陷

记录实际批次、用例/子例、日期/执行人、软件版本、提交和补丁标识、入口、合成样例版本/哈希、准确需求、前置条件、模型实际路由、尝试次数、预期/实际、退出码、输出标识、脱敏证据及结论。未知信息不编造，日期只作追溯，不作排期。

确认缺陷按[登记表](defect_register_v1.0.9.md)填写，稳定编号，单表不超过 60 条。修复需单独授权，限定文件/类/函数；原例回归和影响范围核对完成才关闭。Issue、标签、审核人和发布决定均据实记录，不猜测团队安排。
